# AI 可执行用例·正反例对照集

> 本文件不写规则，写正反例对照样本。每对展示「❌ 不可消费 → ✅ 可消费」的改造路径。
> 写 case 时对照样本判断写法是否到位。

## 准出铁律（不可妥协）

- **不可编造**：不许出现「假设账号是 demo_account」「假设入口为某某页」等自填行为
- **不可占位**：不许出现「测试账号」「某页面」「若干数据」「XXX」等占位词
- **不可跳过**：不许默默忽略 spec 没写的字段不写
- **单线瀑布**：case 是单线消费序列，禁止出现「如果...则...」「若不存在则...」「找不到改用...」「按相同规则...」「重复以上规则」等业务决策分支（**例外**：①登录态归正"如果未登录则登录" ②非业务弹窗"若弹出 XX 对话框点关闭"，这两类系统级状态恢复允许写）。**首选具名 + 精确路径**（用资源在 spec / 用户答复中的真实名字标识），具名是 case 质量上限。**最大可包容**：当作者无法预知具体本名、且环境无法保证唯一具名资源就绪时，允许在步骤里写 **1 个同质筛选**（如"找一个进度为空的资源"），但必须满足：①整条 case 内同质筛选 ≤ 1 个；②筛选维度上的所有候选对验证结论同质（任一候选跑下来都能跑出同样断言）；③步骤后置必须有**反向定位手段**——筛选完操作完之后必须能在结果页把刚操作的那个对象**找回来再断言**（手段类型：最近访问 / 最近编辑标识、聚焦 / 高亮态、名称回查、最后落点位置 等任一种业务真实可见的特征）。**异质决策**（"如果默认筛选不对则切..."、"找不到改用第 2、3 个"、"当前列表无可用切到下一组"）一律禁止——这种判断要么外移给作者写 case 前确定，要么外移给环境工具构造
- **断言唯一**：一条 case = 一个验证点 = **一条断言**（"一条"是计数单位）。这条断言可以是单一视觉特征，也可以**聚合围绕同一观察对象的多个同类视觉特征**（如形态 + 配色 + 进度位置：「进度条约 1/3 填充呈橙色」）；但不可跨对象 / 跨业务面并列（如「进度条 30%」+「当日学习板块也 30%」）。导航类事实（"进入了某页"）、附属状态标识（"进行中标识"）、附加数字（"25%-35%"）一律不写入预期。如出现指向不同对象 / 不同业务面的并列断言（用「；」分隔的多个独立判断）→ 拆成 2 条 case
- **前置 = 纯约束 / 步骤 = 真干活**：前置条件**只允许写 4 类**：①起跑线归零（端类型对应的冷启动动作把系统恢复到 case 验证基线，例：app 杀进程后重启 / web 关闭并重开 Tab / 小程序退出后重进）；②登录态归正（"如果未登录则使用账号 X/Y 登录"）；③元指令（"必须按步骤一步步执行"等准出口径）；④VLM 在步骤里做不了的环境约束（飞行模式 / 接口已 Mock / 后台已操作 X / 跨设备状态预置 / 系统级开关）。**判定准则**：这件事 VLM 在步骤里能不能做？能 → 归步骤；不能 → 才归前置。**资源初始化是环境责任，不是 case 责任**——case 不操心"目标资源在哪 / 状态是不是 X / 业务筛选维度是不是 Y"这类业务事实；环境保证就绪，case 在步骤里靠"筛选 + 后置定位"取用。拦截关键词：前置出现「位于 XX 页」「当前在 XX Tab」「业务筛选维度已切到 XX」（如分类 / 类目 / 命名空间 / 教材-学段-学科-章节-地区-门店等任意业务维度）「目标资源处于 X 状态」 = 一律下放到操作步骤
- **UI 元素必有据**：写进 case 的**每一个 UI 元素**（按钮 / 弹窗 / Tab / 卡片 / 抽屉 / 文本 / 图标 / 控件位置 / 容器层级）必须来自 spec / 截图 / 用户已答复，**不许凭文本视觉预测**（包括"我猜应该有 XX 按钮"、"应该是右上角关闭"、"弹窗里应该有确认"、"应该有底部 Tab"、"应该叫'去做题'"）。每写一个动作步骤都自问：**这个 UI 元素是 spec 里写过的，还是我自己想象的？** 自己想象的 → 立即触发 [execution-context-questionnaire.md](execution-context-questionnaire.md) 反问，禁止落盘。常见踩雷：弹窗的层级结构、按钮的位置 / 文案、容器是否默认展开、Tab 在顶部还是底部、是否有"确认 / 关闭"按钮
- **字段挂载**：标题 / 前置 / 步骤 / 预期 四字段必须显式挂载前缀（`测试标题：` / `前置条件：` / `操作步骤：` / `预期结果：`），不可只写内容省略前缀
- **默认重启**：每条 case 起跑线第一句必须是端类型对应的冷启动动作（移动 App：「关闭 App「xxx」（杀进程）后重新打开 App「xxx」」 / Web：「关闭并重开浏览器 Tab 进入 https://xxx」 / 小程序：「退出小程序后重进」）；只有验证「不重启场景」「跨 case 状态继承」等少数 case 才能省略
- **emoji 禁出现**：case 任何字段（标题 / 前置 / 步骤 / 预期）严禁出现 emoji / 表情符号（如 💡 🔍 ⭐ 📱 ❤ 等）。spec 或 UI 截图含 emoji 时**只引用其文字部分**（例：UI 卡片标题「💡 学习方法」→ case 里写「学习方法」）。原因：emoji 在不同系统 / 字体下渲染差异大、跨端字符宽度不一致，VLM 视觉比对与 OCR 对 emoji 字符识别极不稳定，是断言失败的高发因子
- **颜色必带容差注释**：case 任何字段提到颜色（紫色 / 蓝色 / 红色 / 黄色 / 绿色 / 深色 / 浅色 / 灰色 / 渐变色 等）时，必须紧跟一个 `（颜色仅参考）` 容差注释。写法：`紫色头图区` → `紫色（颜色仅参考）头图区`。原因：spec 写的色是设计稿色，App 实物受主题切换 / 色阶 / 截图压缩影响经常存在轻微偏差；一旦把颜色写死，VLM 严格比对必挂；加容差词后 VLM 按「颜色为辅、形态 / 位置 / 文字为主」判定
- **唯一动作**：feature-list.md 里检索不到或描述模糊 → 按 [execution-context-questionnaire.md](execution-context-questionnaire.md) 反问用户 → 拿到具体答案 → 写入 case → 回到本对照集再次自检

**未按上述铁律补齐的信息出现在 case 文件中，即为不合格 case，禁止输出。**

## 字段挂载与起跑线模板（每条 case 共用）

### 0.1 字段缺前缀挂载 → 显式挂载

❌
【正向】xxx
账号 / 状态 ...
点击 ABC
屏幕显示 ...

✅
测试标题：【正向】xxx
前置条件：账号 / 状态 ...
操作步骤：点击 ABC
预期结果：屏幕显示 ...

> 标题字段也要前缀，与前置 / 步骤 / 预期对齐；不能只写「【场景标签】+ 内容」就完事

### 0.2 起跑线无重启 → 起跑线第一句重启

❌  使用账号 demo_user 登录 App「示例学习」（若 App 已登录则跳过登录）；从首页底部 Tab「学习」进入...
✅  关闭 App「示例学习」（杀进程）后重新打开 App「示例学习」；若进入登录页则使用账号 demo_user_01/Demo@123 登录、若已自动登录则跳过登录；从首页底部 Tab「学习」进入...

> 重启 App 是默认初始化动作，确保每条 case 从同一基线状态出发；执行器每次都从冷启动出发，省去清状态的负担

## 操作步骤

### 10. 缺锚点 → 按钮文案锚点

❌  进入引导页面，依次点击下一步完成引导
✅  点击引导卡片「下一步 →」、点击「下一步 →」、点击「完成 ✓」

> 每步带按钮文案；多步用顿号分隔；不写「等待 N 秒」（机器自动兜底）

### 11. 路径吞掉 → 跳转露出

❌  在章节列表页点击章节
✅  点击底部 Tab「学习」、点击章节列表第一项「第一章 · 有理数」

> 不要省略中间的入口跳转

### 12. 输入占位 → 具体值

❌  输入测试手机号
✅  在「手机号」输入框输入 13800138000

> 输入数据要具体值 + 输入框名称

### 13. 步骤合并 → 拆分原子

❌  完成所有引导步骤
✅  点击「下一步 →」、点击「下一步 →」、点击「完成 ✓」

> 一步一个动作，不要合并

### 14. 抽象动作 → 可执行动作

❌  退出页面
✅  点击页面左上角返回箭头

> 写 VLM 可执行的具体动作，不写「退出 / 进入 / 查看」抽象动词

### 15. 被动等待 → 主动手段

❌  等待视频播放至进度条 30%
✅  长按进度条圆点向右拖至约 30% 位置释放

> "等 90 秒"这种时间观 VLM 没有；被动等待动词改成 click / drag / scroll / press_back 等瞬时动作（页面稳定的等待执行器自动兜底，case 不写）

### 16. 单一退出路径 → 备选并列

❌  点击工具栏左上角返回箭头退回上一页
✅  按物理返回键 / 或点击工具栏左上角返回箭头退回上一页

> press_back 是系统级动作 VLM 失败率最低；业务必须用特定按钮再补"或物理返回键"作备选，避免 VLM 找不到那个按钮就卡死

### 17. 步骤无陷阱 → 陷阱嵌入

❌  点击视频画面中央唤起工具栏、拖至 30%、按返回键
✅  点击视频画面中央唤起工具栏（**3 秒后会自动消失，可再次点击屏幕中央唤起**）、拖至 30%、按返回键（**若弹"确认退出"对话框点「学点别的」**）

> 控件用法 / 陷阱+恢复手段允许在步骤一句话括号嵌入；VLM 没用过这个 App 没有领域常识，必须由 case 显式喂——这是「保洁阿姨原则」的真正落点

## 预期结果

### 18. 抽象判断 → 视觉证据

❌  引导流程正常完成
✅  屏幕显示章节目录树；屏幕无引导卡片；屏幕无半透明遮罩

> 写视觉断言「显示什么 / 无什么」，不写「正常 / 完成」

### 19. 业务正常 → 具体元素

❌  章节列表加载成功
✅  页面顶部显示「初中-数学-人教版-七年级上册」；页面中部显示章节目录树；底部 Tab「学习」高亮

> 「成功 / 正常」要替换成具体可见元素

### 20. 描述动画 → 终态截图

❌  引导卡片向下滑出消失，遮罩淡出
✅  屏幕无引导卡片；屏幕无半透明遮罩

> VLM 是截图式不是视频式；只写终态，不写动画过程

### 21. 多并列断言 → 唯一断言（可含同对象同类特征聚合）

❌  屏幕显示章节列表页；该卡片左上角显示「进行中」标识；该卡片视频进度条非空且填充约 30%；该卡片百分比文字显示在 25%-35% 之间；该卡片做题进度文字仍显示「做题 0/N」
✅  该卡片视频进度条约 1/3 填充呈橙色

> 一条 case = 一个验证点 = **一条断言**。"一条"是计数单位，但这条断言内允许聚合**围绕同一观察对象的多个同类视觉特征**——如「进度条约 1/3 填充呈橙色」是一条（同一对象 + 同类视觉属性：填充比例 + 配色）。
> 删除规则：导航类事实（"屏幕显示 XX 页"）→ 删；附属状态标识（"进行中标识"）→ 删；同义重复（"百分比 25%-35%"与"约 1/3"重复）→ 删冗余；**跨对象事实**（"做题文字 0/N" 指向不同业务面）→ 不能聚合到同一条，拆成另一条 case。
> 剩下的那一条 = 标题里"验证什么"的最直接视觉证据。
> 拆判定：如出现 ≥ 2 条断言、指向**不同对象 / 不同业务面**（如"进度条 30%"+"当日学习板块也 30%"是两个独立验证对象）→ 是 2 个验证点，**拆成 2 条 case**

### 22. 含 emoji → 仅留文字

❌  操作步骤：点击学习方法卡片头部「💡 学习方法」标题行
✅  操作步骤：点击学习方法卡片头部「学习方法」标题行

❌  预期结果：屏幕显示标题为「💡 学习方法」的学习方法卡片
✅  预期结果：屏幕显示标题为「学习方法」的学习方法卡片

> emoji 在 spec / 截图 / 文案里可以保留，但**搬进 case 必须只引用文字部分**。VLM 在不同 iOS / Android / 鸿蒙端对 emoji 渲染、字符宽度、Unicode 解析有差异，OCR 与视觉比对极易错位；上一轮端到端跑出「💡 学习方法」字符级失配大量挂 case，是该铁律的直接来源。
> 落点：标题 / 前置 / 步骤 / 预期 四字段任一出现 emoji → 立即剥离 emoji 仅留中文文字 / ASCII 文字；如剥离后语义不清晰 → 触发 [execution-context-questionnaire.md](execution-context-questionnaire.md) 反问作者确认锚点元素的纯文字名称。

### 23. 颜色写死 → 颜色加容差

❌  预期结果：屏幕首屏顶部显示紫色头图区且头图内显示「教材同步」主标题
✅  预期结果：屏幕首屏顶部显示紫色（颜色仅参考）头图区且头图内显示「教材同步」主标题

❌  预期结果：内容反馈多选区两个 chip 均显示深色背景选中态
✅  预期结果：内容反馈多选区两个 chip 均显示深色背景（颜色仅参考）选中态

❌  操作步骤：点击底部紫色「提交反馈」按钮
✅  操作步骤：点击底部紫色（颜色仅参考）「提交反馈」按钮

> 颜色是 VLM 视觉断言里最易抖动的一类——spec 写的色 = 设计稿色，App 实物受主题 / 色阶 / 屏幕色温 / 截图压缩影响常有偏差。`（颜色仅参考）` 是给 VLM 的明确容差信号，让其按「颜色为辅、形态 / 位置 / 文字为主」判定，绕开颜色失配。
> 落点：扫遍 case 全字段，任一颜色词（紫 / 蓝 / 红 / 黄 / 绿 / 深 / 浅 / 灰 / 渐变 / 高亮 / 透明 等）后 → 检查紧邻是否带 `（颜色仅参考）`；缺则补；不能用「深色」「浅色」「主色」等抽象词代替具体色名（先写具体色再补容差）。
