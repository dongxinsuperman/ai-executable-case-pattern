# 测试设计方法选用指南

根据测试功能点的特征，选用合适的测试设计方法推导用例。同一个测试功能点可能适用多种方法。

---

## 1. 等价类划分

**适用场景**：输入或条件有明确的分类，同类内的值行为一致。

**方法**：
1. 识别输入/条件的有效等价类和无效等价类
2. 每个等价类至少取一个代表值生成用例

**在 Spec 中的典型应用**：
- 用户身份：VIP / 非VIP
- 学科模板：6 套模板各取一个代表学科
- 卡片类型：视频 / 刷题 / 学案 / 读课文 / 总结笔记 / 培优钩子
- 内容权限：免费 / VIP不可试看 / VIP可试看 / 培优

**用例示例**：
```
测试功能点：不同用户身份下VIP内容展示
  【状态】VIP用户查看VIP内容-正常展示无锁定
  【状态】非VIP用户查看VIP内容-展示锁定态
```

---

## 2. 边界值分析

**适用场景**：存在数值范围、时间窗口、数量限制等边界。

**方法**：
1. 识别边界点
2. 取边界值、刚好超出边界值进行测试

**在 Spec 中的典型应用**：
- NEW 徽标 7 天窗口：第 1 天、第 7 天、第 8 天
- 视频进度：0%、中间值、99%、100%
- 刷题进度：0/N、中间值、N/N
- 试看倒计时：剩余 1 秒、归零
- 章节数量：0 章、1 章、大量章节
- Tab 数量：≤4（不滑动）、>4（需滑动）

**用例示例**：
```
测试功能点：NEW徽标显示时间边界
  【边界】发布恰好7天的节-应显示NEW徽标
  【边界】发布超过7天的节-应隐藏NEW徽标
```

## 3. 状态转换法

**适用场景**：系统存在明确的状态集合和转换条件。

**方法**：
1. 从 Spec 中提取状态集合
2. 从状态流转描述中提取转换事件
3. 为每个有效的"起始状态 + 事件 → 目标状态"组合生成用例

**在 Spec 中的典型应用**：
- 学习状态：未开始 → 进行中 → 已完成
- 抽屉状态：关闭 → 展开 → 关闭
- 引导流程：第1步 → 第2步 → 第3步 → 完成
- 学习方法卡片：折叠 → 展开 → 折叠
- 学习模式偏好：无偏好 → 有偏好 → 每次询问

**用例示例**：
```
测试功能点：学习状态流转
  【状态】未开始资源首次产生进度-状态变为进行中
  【状态】进行中资源视频和做题均100%-状态变为已完成
  【状态】已完成资源重新点击-保持已完成不回退
```

## 4. 判定表法（条件组合）

**适用场景**：多个条件组合决定不同的系统行为。

**方法**：
1. 列出所有条件
2. 列出每个条件的取值
3. 组合条件，确定每种组合下的预期行为
4. 对规模较大的组合做合理裁剪（合并无差异行）

**在 Spec 中的典型应用**：
- 标签筛选：contentTag × sceneTag 的 AND/OR 组合
- 卡片点击行为：VIP状态 × 内容权限 × 试看支持 → 正常播放/锁定/试看
- 内容选择弹窗：学习状态（未开始/进行中/已完成）× 卡片类型 → 是否弹窗
- 复习偏好：有偏好/无偏好 × 场景Tab（复习/非复习）→ 弹窗/直接进入/不触发

**条件组合示例**（卡片点击行为）：

| 用户身份 | 内容权限 | 支持试看 | 预期行为 |
|---------|---------|---------|---------|
| VIP | 免费 | — | 正常进入 |
| VIP | VIP专属 | — | 正常进入 |
| 非VIP | 免费 | — | 正常进入 |
| 非VIP | VIP专属 | 是 | 展示试看+升级入口 |
| 非VIP | VIP专属 | 否 | 展示锁定+升级引导 |

## 5. 场景法

**适用场景**：端到端的业务流程，涉及多个功能点串联。

**方法**：
1. 从 Mermaid 流程图中识别从入口到出口的完整路径
2. 选取基本流（happy path）和主要备选流
3. 为每条路径生成一条端到端用例

**在 Spec 中的典型应用**：
- 完整学习流程：进入页面 → 选教材 → 选章节 → 切Tab → 点卡片 → 学习 → 返回更新进度
- 首次引导流程：进入 → 第1步 → 第2步 → 第3步 → 完成 → 正常使用
- VIP 转化流程：非VIP看到锁定 → 试看 → 试看结束 → 升级 → 返回解锁

**注意**：场景法用例通常较长，操作步骤多。在写为单行时，用顿号分隔保持可读性。

## 6. 错误推测法

**适用场景**：基于经验预判容易出 bug 的场景。Spec 中未明确提及但实际容易出问题的点。

**常见关注点**：

| 类别 | 典型场景 |
|------|---------|
| 快速操作 | 快速连续点击、快速切换 Tab、快速滚动 |
| 并发/竞态 | 滚动联动时同时点击节点、Tab 切换时资源还在加载 |
| 网络波动 | 加载中断网、弱网环境、网络恢复后状态同步 |
| 数据不一致 | 本地缓存与服务端数据冲突、进度数据异常 |
| 空数据/满数据 | 无章节、无资源、单个资源、大量资源 |
| 时序问题 | 返回页面时数据未刷新完成、动画进行中操作 |

**用例示例**：
```
测试功能点：快速操作容错
  【异常】快速连续点击3个不同目录节点-以最后一次为准
  【异常】Tab切换时资源尚在加载中再次切换-不出现数据错乱
```

## 方法选用决策表

根据测试功能点的特征快速判断适用方法：

| 功能点特征 | 首选方法 | 辅助方法 |
|-----------|---------|---------|
| 有明确的输入分类 | 等价类划分 | 边界值 |
| 有数值/时间边界 | 边界值分析 | — |
| 有状态流转图 | 状态转换法 | 场景法 |
| 多条件决定行为 | 判定表法 | 等价类 |
| 端到端流程 | 场景法 | 错误推测法 |
| 交互复杂/易出bug | 错误推测法 | 场景法 |
