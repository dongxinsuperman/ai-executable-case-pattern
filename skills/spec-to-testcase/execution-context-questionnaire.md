# 执行上下文反问规范

> 本文件规定：写 case 时如果信息**检索不到**或**描述模糊**，必须反问用户补齐，不靠猜。
> 与 [ai-executable-rules.md](ai-executable-rules.md) 互为门禁——前者定义「什么样的 case 可消费」，本文件定义「信息缺口怎么补齐」。

---

## 准出铁律（不可妥协）

- **检索不到就问**：feature-list.md 里没写的 → 必须反问，不靠猜
- **模糊就问**：spec 里写了但表述模糊（如「测试账号」「若干数据」「正常环境」「后台清除」）→ 必须问到具体值 / 具体工具 / 具体路径
- **决策点必反问**：写完一条 case 后回扫文本，若出现「若...则...」「找不到改用...」「不存在则...」「按相同规则...」「重复以上规则」等决策性结构 → 禁止落盘，必须反问用户「这条 case 实际跑的时候是哪一支？请直接给确定值，不要写如果」
- **资源筛选必反问**：case 里出现异质筛选规则（"第 N 个 / 满足 XX 条件的 / 任意一个 / 找一个..."这类无法保证候选同质的描述）→ 必须反问拿到资源具体本名（按业务领域填：商品名 / 订单号 / 视频名 / 章节名 / 文档名 等）。**步骤里 1 处同质筛选 + 后置反向定位**允许保留（参见 [ai-executable-rules.md](ai-executable-rules.md) 第 22 条），但需自检：候选是否同质、是否有反向定位手段
- **必要条件触发路径必反问**：case 涉及任何"先做才到"的非默认前提（资源态 / 业务态 / 账号身份 / 权限 / 灰度命中 / 配置项 / 数据准备 等——如 进行中 / 已完成 / 已开通会员 / 已加入班级 / 已选学段 / 已生成 5 条历史 等）→ 必须反问「**走到该前提的具体路径是什么？** ① 能由 case 步骤触发到位的（如视频进度、做题数据）→ 步骤路径写进操作步骤；② 只能靠预置的（如灰度开关 / VIP 身份 / 班级状态）→ 给具体工具或预置账号写进前置条件」。**禁止**把"已处于 X 态 / 已开通 / 已加入"作为前置事实塞入而不说怎么到位。如果作者无法预知具名资源，允许在步骤里走"找一个进度为空的资源 → 自己触发到目标态 → 验证"这种路径（同质筛选 ≤ 1 处 + 后置反向定位，参见 [ai-executable-rules.md](ai-executable-rules.md) 第 22 条）
- **UI 细节必反问**：写每个动作步骤前自问"这个 UI 元素是 spec 写过的，还是我自己想象的？"。凡是 spec 没明示的 UI 元素（按钮位置 / 弹窗层级 / 控件文案 / Tab 位置 / 容器展开状态 / 入口元素是否存在）→ 必须反问拿到真实形态或截图，**禁止凭文本视觉预测**。常见踩雷：①「点击 X 区域唤起 X 弹窗」（弹窗结构是猜的）；②「右上角关闭按钮」（按钮位置是猜的）；③「底部 Tab」（Tab 位置是猜的）；④「滚动到第 X 项 / 第 X 节」（容器是不是默认展开是猜的）；⑤「卡片下方的某入口」（入口元素是不是真存在、文案是不是这个，是猜的）
- **异常注入工具必反问**：case 是【异常】场景（网络错误 / 接口失败 / 数据异常 / 权限不足 / 极端边界值 等）→ 必须反问「**触发异常的具体工具 / 路径是什么？写到步骤字面级**——如"通过手机系统设置打开飞行模式"、"通过网络代理工具将 XX 接口响应改为 500"、"通过测试数据后台将该账号会员状态置为未开通"」。不允许出现「手机已断网」「接口已注入失败」「网络异常」这种没说怎么造的占位描述——VLM 在异常场景里最容易卡的就是"该用什么手段触发"
- **未问就不写**：信息缺口未问到具体答案前，禁止写入 case
- **写完再自检**：反问得到答案后写入 case，必须回到 [ai-executable-rules.md](ai-executable-rules.md) 对照样本再次自检
- **轮数不限，问到 7 类信号全部归零才放行**：允许批量攒问、用户答复后再次回扫整批 case；只要还有任一类信号未清，继续反问。不存在"问过一两轮差不多就放行"的豁免——case 模糊 → 后续执行全模糊，必须明确每一处。每轮反问应保持单点清晰：一个问题问一件事，避免在同一句里塞多个问题（用户答复时容易驴唇不对马嘴，反而给 AI 增加模糊）

**未按上述铁律补齐的信息出现在 case 文件中，即为不合格 case，禁止输出。**

## 触发时机

全流程触发，不分阶段。case 的任一字段（标题 / 前置 / 步骤 / 预期）出现以下 7 类信号即立即反问。

| # | 信号 | 含义 | 示例 |
|---|------|------|------|
| 1 | **spec 检索不到** | feature-list.md 里没写到（关键词缺席） | 账号 / 包名 / 工具 / 入口路径 |
| 2 | **spec 描述模糊** | spec 里写了但表述含糊（命中模糊词典） | 「测试账号」「若干数据」「正常环境」「后台清除」 |
| 3 | **决策结构** | case 文本出现「如果A则B」（系统级状态恢复除外） | 「若默认教材不对则切..」「找不到改用第 2、3 张」 |
| 4 | **资源筛选规则** | 用规则替代具体名字（步骤里 1 处同质筛选+后置定位允许） | 「第 1 张未开始视频卡片」「任意一张...」「找一张..」 |
| 5 | **必要条件触发路径** | case 涉及"先做才到"的非默认前提，但没说怎么准备到位（步骤触发或预置就绪二选一） | 「视频已是进行中态」「已开通会员」「已加入班级」「已选学段」「已生成 5 条历史」「灰度命中」 |
| 6 | **UI 元素无据** | spec 没明示却写进了具体 UI 描述 | 「右上角关闭按钮」「底部场景 Tab」「在弹窗中依次点击 A B C」「页面中部蓝色圆形快捷按钮」「卡片下方的「去做题」入口」「滚动到第 X 章第 X 节」 |
| 7 | **异常注入工具** | 【异常】case 触发异常的工具 / 路径 spec 没写到字面 | 「手机已断网」（没说飞行模式 / 拔网线 / 网络代理工具）「接口已注入失败」（没说工具）「网络异常」（没说怎么造） |

- 一次问不完没关系，允许多次反问
- 但不能漏：单条 case 输出前所有缺口必须补齐
- **回扫义务**：写完 case 后必须回扫一遍，命中任意一项即不合格、回到反问 / 改写
- **优先要截图**：信号 6 触发时，文字描述往返成本高，主动向用户索要 App 当前页截屏 / 录屏，一次解决多个 UI 不确定
- **断言聚合 / 前置塞业务事实不在反问规范里**：预期是否多条断言、前置是否塞业务事实，是写法层格式问题（详见 [ai-executable-rules.md](ai-executable-rules.md) "断言唯一" + "前置 = 纯约束 / 步骤 = 真干活" 两条铁律），由 Phase 4 写法 lint 拦截而不是反问

## 反问方式

- **不必给选项**——既然 spec 里检索不到，给选项就是 AI 在猜，宁可开放式提问
- **不必一次问完**——按字段出现顺序分次问，问到哪写到哪
- **必须问到具体值**——例如要拿到「测试数据后台 → 用户状态 → 重置标记按钮」这种具体路径，不接受「靠后台清就行」这种含糊回答
- **决策点反问要明示约束**——针对信号 3-7 的反问，问句末尾要明示「请直接给确定值，不要写如果」「请给资源具体本名」「请给前提到位的具体路径——能由步骤走的写步骤、靠预置的写预置工具」「请描述真实 UI 形态或直接发截图」「请给异常注入工具到字面级」，否则用户答得回来仍是含糊的
- **答案不落盘**——仅用于本次生成过程

## 反问的常见场景（示例，可按业务扩增）

> 不是必问清单，是「通常 spec 不会写」的场景示例。实际只要检索不到 / 模糊都要反问。

| 场景 | 通常缺什么 | 反问示例 |
|------|----------|---------|
| 涉及登录态 | 具体账号 / 密码 / 包名 | 本次用什么测试账号？App 包名是什么？ |
| 涉及业务前置数据 | 数据如何构造 | 这个状态用什么工具构造？后台按钮 / SQL / 接口？ |
| 涉及入口路径 | 从哪到被测页 | 启动 App 后到被测页面的完整跳转路径是？ |
| 涉及上新 / 配置型功能 | 后台配置工具 / 字段 | 后台在哪里创建？需要填哪些字段？是否走 SQL？ |
| 涉及异常注入 | Mock 工具 / 触发方式 | 异常用什么工具注入？网络代理工具 / 后端开关 / Debug 菜单？ |
| 涉及 AB 灰度 | 哪个分支 / 怎么进 | 本次覆盖哪个分支？怎么让账号命中该分支？ |
| 涉及具体输入数据 | 用什么值 | 这个输入框输入什么值？ |
| 涉及非业务弹窗 | 自动关闭策略 | 测试环境会出现哪些非业务弹窗？允许自动关闭吗？ |
| 涉及环境隔离 | 域名 / 包名 / 数据隔离 | 测试环境域名 / 包名是？是否与生产数据隔离？ |
| **case 出现「如果A则B」** | 实际是 A 还是 B | 这条 case 实际跑时是哪一支？请直接给确定值，不写"如果" |
| **资源筛选规则** | 资源具体名字 | 这条 case 用哪个具体的视频/章节/卡片？请给本名，不写"第 N 张/未开始的" |
| **必要条件触发路径** | 前提如何到位 | 这条 case 涉及什么非默认前提（资源态 / 身份 / 班级 / 会员 / 灰度 / 教材已选）？① 能由步骤触发的请给步骤路径写进操作步骤；② 只能靠预置的请给具体工具或预置账号写进前置——禁止"已处于 / 已开通 / 已加入"作为前置事实 |
| **被动等待动词** | 能否改主动 | "等待播放至 30%" 能否改成"拖拽进度条至 30%"？避免 VLM 长时间等待超时 |
| **UI 元素无据**（最容易踩） | 真实 UI 形态 | 这一步要点击的元素 spec 没写过——它真的存在吗？文案是？位置是？是按钮 / 弹窗 / Tab / 卡片中的哪种？**直接发当前页截屏最快** |
| **弹窗结构无据** | 弹窗层级 | 这是 1 个弹窗逐层选还是 N 个独立选择器？选完是即时生效还是要点确认？怎么关闭？请描述或截图 |
| **容器是否默认展开** | 默认状态 | 这个容器（树 / 抽屉 / 折叠面板）默认是展开还是隐藏的？打开它的具体动作是什么？ |
| **异常注入工具** | 异常怎么造 | 这条【异常】case 用什么工具触发？飞行模式 / 拔网线 / 网络代理拦截 / 后端开关 / Debug 菜单 / 测试数据后台造数据？写到步骤字面级，不写"已断网 / 已注入失败"这种占位 |

## 与 ai-executable-rules 的闭环

```
对照 ai-executable-rules 样本写「✅ 版」
        ↓
发现 feature-list.md 检索不到 / 模糊？
        ↓
触发本文件反问 → 用户答具体值 → 写入 case
        ↓
回到 ai-executable-rules 对照样本再次自检
        ↓
通过 → 输出；不通过 → 回到第 1 步
```
